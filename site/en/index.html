It runs real software

Unedited capture from a real machine (QEMU, frame-by-frame): one command in the terminal pulls an app package from the host, aetherd installs htop, and it runs on the self-written desktop.

Why it is different

The kernel is not rewritten — Android and ChromeOS use the Linux kernel too, and rewriting it buys nothing. All the effort goes above it.

Nothing above the kernel is off-the-shelf

From PID 1 to the compositor, terminal (own PTY + VT parser), IME and AI hub. The compositor writes straight to the framebuffer, with tiling, shadows, rounded corners, dirty-row upload and adaptive frame rate.

It installs real Linux software

Static binaries and common dynamic dependencies work; the image ships ncurses + terminfo, zlib, openssl, libffi and expat. The package format and installer are custom too.

AI hub with per-tool permission gating

Every tool call passes a gate; L2+ actions raise a confirmation dialog and are audited. The architecture is client → your own gateway → any model, so no upstream API keys live on the machine.

The whole system is 38.5 MB

Small enough to boot with one command. Zero compiler warnings on both targets, 19 UI screenshots regression-checked pixel by pixel.

FAQ

Why the Linux kernel instead of writing your own?

Rewriting the kernel buys nothing — Android and ChromeOS use it too. The product difference lives above it, and above it everything is written from scratch. More in the FAQ.

Can I use it daily?

It is an early v0.1.0 release: great for experimenting and development, not recommended for important data yet.

How do I install software?

wget -O- <package-url> | sh — the custom package format plus aetherd. Static binaries and common dynamic dependencies work.

Where does the AI hub send my data?

Nowhere by default: the system talks to your own gateway, which talks to the model provider. No upstream API keys are stored, and every tool call passes a permission gate.
