常见问题

关于定位、能力与边界。没找到答案就到 Issues 提问。

为什么用 Linux 内核，而不是自己写一个内核？

因为重写内核没有差异化价值。Android 与 ChromeOS 都用 Linux 内核，它们的产品差异全在用户态。 一个 hobby OS 花几年写一个跑不了真实软件的半成品内核，换来的只是"内核是自己写的"这句话； 而把力气放在内核之上，得到的是一个能装真实软件、有完整桌面体验的系统。

本项目真正的差异化在内核之上那一层，而且那一层没有一行是现成的： PID 1、窗口合成器、终端模拟器（自写 PTY + VT 解析器）、中文输入法、AI 中枢与 IPC 协议。

系统里到底哪些是自己写的？

Linux 内核与 Buildroot 提供的交叉工具链/根文件系统基础设施不是；其余全自研，共 7 个 Rust crate、24,388 行代码（45 个源文件）：

  • aether-init：PID 1，服务编排、持久化分区、串口日志、故障自愈
  • aether-compositor：窗口合成器，直接写 framebuffer，含窗口管理、平铺布局、阴影圆角、脏行上屏
  • aether-shell：顶栏
  • aetherd + aether-ipc：AI 中枢与线协议（NDJSON over TCP）
  • aether-install：安装向导；aether-ops：运维与自检
  • 终端、中文输入法、回收站、应用包格式
能当日常系统用吗？

目前是 v0.1.0 早期版本：适合体验、开发、试验与二次开发， 不建议承载重要数据或当作唯一工作机。它能装真实软件、能装到虚拟磁盘持久化引导 —— 欢迎试用并到 Issues 反馈问题。

怎么安装市面上的 Linux 软件？

用自研的应用包与 aetherd：

wget -O- <包地址> | sh

静态二进制与常见动态依赖都能跑；镜像已补齐 ncurses + terminfo、zlib、openssl、libffi、expat。 已实测运行 Ubuntu 24.04 官方仓库的 htop 3.3.0。打包说明见仓库 docs/APP-PACKAGES.md。

AI 中枢会把我的数据发到哪里？

架构是客户端 → 你自己的网关 → 各家模型：系统里不存放上游 API Key， 换模型不需要改系统。每一次工具调用都要过权限闸门， L2+ 操作（写文件、执行命令等）会弹确认框，并把允许/拒绝记进审计日志。

和别的自研系统 / Linux 发行版有什么不同？

发行版是"把现成组件组装起来"：现成的 init、现成的桌面、现成的终端。本项目是 从 PID 1 往上自己写，同时保留"能装真实软件"这条底线 —— 这两件事同时做到的项目很少。

为什么 ISO 只有 38.5 MB？

因为里面没有庞大的桌面环境：合成器、终端、输入法都是自己写的，体积由我们控制。 内核与基础设施来自 Buildroot，字体是构建期按 GB2312 + 拉丁子集化生成的（约 5.7 MB）。

需要什么硬件？

64 位 x86 虚拟化环境、1 GB 内存起、支持 1024×768 的显示适配器。已在 QEMU / VirtualBox / VMware 三个平台实测开机；真实硬件通常可用，但当前以虚拟机为主要验证环境。

界面支持中文吗？

支持。界面字体是自带的 Noto Sans CJK SC 子集（含真粗体），并自研了拼音输入法与候选框。 浅色为默认主题，可在设置中心或控制中心切换深色。

怎么反馈问题、怎么参与开发？

到 GitHub Issues 提问题。能复现的 bug 请带上： 虚拟机平台与版本、AetherOS 版本号、串口日志（见下载页的排错一节）。 想直接参与可以提 PR。
