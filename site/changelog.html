# 2026-10-14：装机验证 + 依赖 CVE 收口 + 审计文档纠偏

一、装机验证（台账 #33 后半段）—— 四项判据全过

此前 ISO 重建好了、isohybrid 也验证了，但没有人真的装过一次机。今天做了：

步判据实测
① 起 ISO系统起来、五服务 ✓巡检#1 … 服务=aetherd=✓ compositor=✓ getty=✓ network=✓ ops=✓
② 安装器目标盘出现分区、持久化分区建好sda: sda1 sda2 + EXT4-fs (sda2): mounted … / unmounting …
③ 从盘引导拔掉光驱也能独立引导[aether-init] 持久化分区已挂载: /dev/sda2 -> /var（nodev,nosuid,errors=remount-ro）
④ 持久化重启后 /var 的写入仍在探针 probe-1014 重启后仍在盘上；/var/boot.log 记录 第 1 次 → 第 2 次 递增

证据：装机验证（INSTALL-VERIFY）-2026-10-14.md

在哪做的、以及为什么不是构建机（如实记）：

* 构建机内的 QEMU 是三层嵌套（Hyper-V → VirtualBox → QEMU）。QEMU 一起来，

guest 的 sshd 就饿到无法完成认证（paramiko 与 OpenSSH 都报

Connection timed out during banner exchange）；把构建机 2 vCPU 加到 4 vCPU 也没救。

* 于是改在宿主上的 VirtualBox（headless）做：按键注入可用、串口落盘（全部观测都是文本）、

启动只要 10 秒。复现命令写进了证据文件。

* 顺带得到一条自动化经验：注入的按键会被合成器（evdev 直读）与 tty1 的 getty 同时看到 ——

安装命令既进了 AI 指令条、也进了 root shell。所以"AI 栏有没有收到"不能当按键送达的判据。

没覆盖的（别当全绿）：真机（#32）仍要物理机；安装器的交互式路径与 --wipe 破坏性路径本次没走。

十三、找到"站点再也更新不了"的真正根因：patch_values 崩溃

根因（一行代码）

```python

# 错：整条正则（含环视 (?<![\d,])）也被塞进"替换串"

re.sub(pattern.replace("%OLD%", re.escape(o)), pattern.replace("%OLD%", n), text)

```

re.sub 的替换串同样会被当模板解析 → 替换串里的 \d 触发

re.error: bad escape \d at position 5 → 渲染循环直接抛异常中断。

为什么表现为"静默永不更新"

旧代码的顺序是先写 data.json 再渲染：

1. data.json 已改成新值；

2. 渲染抛异常 → 页面一个都没写；

3. 下次运行 o == n → num() 里 if o and n and o != n 不成立 → 连替换都不尝试 → 不崩溃；

4. 页面永远停在旧值，门禁只报"页面与数据脱节"，看不出原因。

这与用户此前修的"站点再也更新不了"是同一个 bug —— 之前的修复让门禁能报出来，

但没有修到崩溃点本身。

修法

```python

text = re.sub(pattern.replace("%OLD%", re.escape(o)), lambda _m: n, text)

```

替换用 lambda：既只放新值，又彻底不经过模板解析（新值里出现 \ 也不会再炸）。

二十、功能缺口：声音（2026-10-03 凌晨，批次 K-1 / K-2）

对应 FEATURE-GAPS §2.2「完全没有音频栈」。后端与界面分两批做。

最重要的决定：不链接 libasound

alsa-sys 需要在交叉编译目标上有 libasound 的头与库 —— 那会让本仓库现有的

musl 静态检查（6/7 crate 可查，合成器正是其中之一）直接失效，代价太大。

我们真正需要的只有两件事：播一个短提示音、读写 Master 音量。于是走 alsa-utils：

aplay -q -（WAV 从 stdin 读，不需要临时文件）与 amixer get/set Master。

零构建期依赖、零新增第三方 crate。附带好处：aplay -l 失败恰好给出一个**可靠的

"有没有声卡"判据** —— 而"无设备时如实显示"是本项目的硬要求。

代价写清楚了：每次提示音起一个子进程（10~30ms 延迟，提示音可接受）；

音量读写同样走子进程，所以不能每帧调用（只在启动/改完时 refresh）。

提示音：运行时合成 WAV，不内嵌音频文件

一段 60~160ms 的正弦音只有几十行代码，而内嵌二进制资源既无法在代码审查里核对，

也会让"这声音到底是什么"变成黑箱。合成还让三条性质变成可测的：WAV 头合法

（逐字段核对 RIFF/data 长度）、不是静音（峰值 > 1000）、三种音可区分（音高/时长不同）。

三种提示音：确认卡片弹出（880Hz，需引起注意）、AI 回复完成（1320Hz，轻）、

操作失败（440Hz，更长）—— 失败与成功听感可分，用户不必盯屏幕。

二十二、功能缺口：电源管理 / 息屏（2026-10-03，批次 M-1）

对应 FEATURE-GAPS §3.6「无空闲熄屏、无休眠 —— 实机费电」。本批做息屏

（休眠涉及整机状态保存，不在本批）。

写内核 blank 接口，不是"自己涂黑屏幕"

set_fb_blank() 写 /sys/class/graphics/fb0/blank（4 = POWERDOWN / 0 = UNBLANK）。

不自己在帧缓冲上涂黑：那只让画面看起来黑了，输出与背光照旧 —— 实机上等于没省电，

而用户会以为系统卡死了。fb0 不存在时依次退到 fb1/fb2，都不行就打一行日志如实报错。

判定是纯函数，所以不必等十分钟就能验

Settings::should_blank(Duration) 拿 Duration 而不是 Instant ——

"阈值前不息、阈值后息、0 = 永不舍弃"三条边界可以在单测里当场验，

而不是靠"设成 1 分钟然后盯着屏幕看"。

几个刻意的决定

* 0 = 永不是一个能选中的档，不是"没设置"。演示与排障时需要它；

若把它当成"未设置"而回落默认值，用户选了"永不"却仍被息屏 —— 那是最恼人的一类 bug。

* 档位固定（0/5/10/30 分钟），非法值吸附到最近档：手工改过的设置文件

不会让界面出现"高亮没落在任何按钮上"的状态。

* 默认 10 分钟（主流桌面系统的默认行为）—— 默认值本身值得说明：它意味着

开箱即用就带息屏，而不是"缺省等于没这个功能"。

* 任何输入都重置计时，且不吞掉那次输入：息屏时按的第一个键就是用户想按的键。

重置放在事件处理之前 —— 放后面的话，被 continue 掉的分支（终端按键）不会重置，

于是"在终端里一直打字"反而会被息屏。

二十三、增强项：性能 HUD（2026-10-03，§5.10）

对应 FEATURE-GAPS §5.10「显示真实帧时间/内存，不造假数据」。

数据是真的，拿不到就写"不可用"

帧时间取上一帧耗时（本帧还没画完）；内存读 /proc/self/statm 的常驻页数。

非 Linux（开发机预览）没有 /proc，HUD 就显示「不可用（非 Linux：无 /proc）」——

绝不编一个数字：HUD 的全部价值就在"数字是真的"，编一个等于把工具废掉。

三条自我约束

默认关（排障工具，不是常显装饰）；不登记命中区（不拦截点击）；

画在 toast 之前（不盖住用户正在看的提示）。

一个真实的边界：0 毫秒不能除零

帧时间为 0 会真的出现（第一帧、计时精度不足）。1000.0 / 0.0 得到 inf，

显示 "inf fps" 比不显示还糟。抽成纯函数 perf_hud_text() 并显式判断 ——

于是"0 毫秒显示 0 fps 而不是 inf"是可测的，不必靠眼睛在真机上撞见。

接线方式

HUD 文本作为 Renderer::perf_text 由主循环每帧喂进来，而不是绘制层自己从 settings

现算：帧时间与内存只有主循环知道，绘制层去读 /proc 会让"画一帧"带上 IO。

副作用是 UiState 的 4 处构造点都不用改（少一次机械改动 = 少一类遗漏）。

二十四、功能缺口：通知中心（2026-10-03，§3.2）

对应 FEATURE-GAPS §3.2「只有 toast（合成器本地状态）—— 错过就没了」。

分四个提交：纯逻辑模块 → 接线 → 看得见 → 设置页。

为什么单独一个模块

toast 在 main.rs 里有 47 个产生点。这里只放纯逻辑（容量、合并、未读），

接线是另一件事 —— 于是"历史上限多少、连续重复怎么合并、未读怎么算"能被单测钉住。

三条规则：有界（50 条，一个跑几个月的桌面不该因为通知越攒越多而变慢）、

连续重复合并（3 秒窗口内同一文本+类别合并并累加次数，不合并的话历史会被刷满，

等于把功能废掉；合并不刷未读）、压成一行（多行/控制字符/ESC 必须去掉 ——

通知文本可能来自外部 IPC 错误信息，原样显示进界面就是注入）。

47 处接线：统一走一个函数

push_toast(&mut toast, &mut renderer.notifs, msg, kind)。

不这样做的话，迟早有人只改一处（新加的提示不进历史），而"历史不全"比"没有历史"更糟

—— 用户会以为没发生过。kind 由调用点给（不在函数里猜文本），

3 处真正的成功提示标为 Ok，6 类失败文案标为 Err。

历史挂在 Renderer 上而不是主循环局部变量：两个事件循环都要写它，

局部变量得声明两份，而"只给其中一个接线"正是产生静默不一致的那类改动。

让它看得见：复用文本预览窗口

没有新造 WinKind：多一种类型就要多一套绘制/滚动/命中处理，而通知列表本就是

"只读文本 + 时间戳"，预览窗口已经把这套做完了。打开即清未读、历史不删、

空历史也能打开并给出说明、已开着就就地刷新不叠第二个窗口。

控制中心那行显示真实未读数（没有未读时不显示数字）。

两处刻意的取舍

1. 清空不把自己记进历史：那条"已清空 N 条"会被记回刚清空的历史，

用户点完看到的仍是 1 条 —— 像没生效。这是"统一走 push_toast 以免漏记"的唯一例外。

2. 两种"空"分开说：记录开着 →「还没有通知」；记录被关掉 →

§5.1 AI 动作撤销（fbbb8e4）

Ctrl+Z 撤销 AI 的桌面改动。关键设计：撤销栈不存窗口 ——

Win.term 是活的 PTY 会话（term::Terminal），本质不可克隆，

所以"撤销关窗"不能靠存整份窗口实现。改为只记逆操作所需的最少数据：

AI 动作记什么撤销怎么做
layout_set上一份布局 + 每个窗口的浮动标志还原 + 重新平铺
open_app新窗口下标关掉它
close_active一个"不可撤销"标记明确告知撤不了，并停下

为什么关窗要记标记而不是什么都不记：不记的话 Ctrl+Z 会跳过它去撤销更早的

布局改动 —— 用户看到布局变了会以为"撤错了东西"。宁可如实说撤不了，也不做假撤销

（"只记标题位置"那种内容回不来）。浮动标志也必须一起还原，否则原本浮动的窗口

继续被平铺，用户会认为"撤销没生效"。

§5.2 审计日志导出（287e8b9）

动手前先查现状："看"早已存在（权限页显示总数/拒绝/失败/路径 + 最近 8 条，

还显式统计无法解析的行数）。所以只补导出：audit::export_text()（纯函数）+ 按钮，

是最误导人的静默失败）、每条同时给原始 Unix 秒与相对时间。

二十六、功能批次：DNS 可改（§2.4 网络写入 · 后端）（2026-10-03）

设置中心的「网络」页此前只能看不能改（读 /proc/net/* 与 /etc/resolv.conf）。

本批补上写入的后端半边，UI 输入控件随后。

范围决策：只做 DNS

查过仓库后确定：/etc/resolv.conf 是真实被消费的路径（网络页显示 DNS + libc 解析），

写完立即生效。而静态 IP 不做 —— 地址由 busybox udhcpc（DHCP）拉起，仓库里没有

ifupdown；要让静态 IP 生效并持久，必须先有一个 aether-init 侧的开机消费者。

只写一个没人读的配置文件，用户会以为"设置生效了"而实际没有：那是假功能，

比明确不做更坏。

安全设计（这是"改系统配置"的接口）

关注点做法
键名SettingKey 白名单枚举（不是任意字符串）—— 未知键在解码阶段就被拒，不给"键名流到拼路径处"留口子
值纯函数校验：1~3 个 IPv4 点分四段地址；IPv6 明确拒绝并说明；前导零、回环、注入形状一律拒
写入原子：临时文件 → fsync → rename → 目录 fsync。直接 fs::write 会先截断，解析器可能读到空文件（难复现的偶发解析失败）
符号链接拒绝覆盖：/etc/resolv.conf 常被其它解析器做成链接，跟着写会改到没打算改的目标（与安全审计 H-4 同一教训）
备份只做一次：保留原系统文件，而不是我们上次写的内容
失败不碰文件：校验不过即返回，不留半成品
鉴权必须由已注册的 UI 通道发起（与服务控制同门槛）。不开给 AI 工具：AI 动作要经确认卡片，而改 DNS 的正确入口是用户在设置页明确输入 —— 一条路径比两条更容易审
审计成功 / 失败 / 拒绝三态都留痕，回答"有没有人试图改设置、被什么挡下"

验证

* cargo test 473 项全绿（+7：aether-ipc 1、aetherd 6）

* 边界用例覆盖：空值、超 3 个、IPv6、段数不足/过多、越界、前导零、; reboot、

换行注入、回环、域名；写入前文件原样不动；备份不被二次覆盖；无残留临时文件；

符号链接被拒（unix 专属用例）

未实机验证：真机上写入 /etc/resolv.conf 后解析是否立即生效（本机是 Windows）。
