十三、找到"站点再也更新不了"的真正根因：patch_values 崩溃

根因（一行代码）

```python

# 错：整条正则（含环视 (?<![\d,])）也被塞进"替换串"

re.sub(pattern.replace("%OLD%", re.escape(o)), pattern.replace("%OLD%", n), text)

```

re.sub 的替换串同样会被当模板解析 → 替换串里的 \d 触发

re.error: bad escape \d at position 5 → 渲染循环直接抛异常中断。

为什么表现为"静默永不更新"

旧代码的顺序是先写 data.json 再渲染：

1. data.json 已改成新值；

2. 渲染抛异常 → 页面一个都没写；

3. 下次运行 o == n → num() 里 if o and n and o != n 不成立 → 连替换都不尝试 → 不崩溃；

4. 页面永远停在旧值，门禁只报"页面与数据脱节"，看不出原因。

这与用户此前修的"站点再也更新不了"是同一个 bug —— 之前的修复让门禁能报出来，

但没有修到崩溃点本身。

修法

```python

text = re.sub(pattern.replace("%OLD%", re.escape(o)), lambda _m: n, text)

```

替换用 lambda：既只放新值，又彻底不经过模板解析（新值里出现 \ 也不会再炸）。

部署脚本踩的坑（值得记住）

vmrun start 会拉起 VMware GUI，GUI 子进程继承了 stdout 管道 ——

subprocess.run(..., capture_output=True) 会永远等不到 EOF 而挂死。

ISO 其实已经部署成功、虚拟机也在跑新构建，但脚本卡在第 3 步不动。

教训：调用会拉起 GUI 的程序（vmrun/vmplayer 等）时，

要么 stdout=subprocess.DEVNULL，要么加超时 —— 不能无超时地捕获输出。

*Correction (2026-10-02): the disk-install claim does not hold for the ISO shipped with this release —

it was measured to have no MBR signature (not isohybrid), so it cannot be written to a disk and booted.

Booting and the live desktop are unaffected. The build script now applies isohybrid; a rebuilt ISO will

support installation.*
