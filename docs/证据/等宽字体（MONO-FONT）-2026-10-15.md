# 等宽字体收口（台账 #46）—— 2026-10-15

> 台账 #46 记的是 `text.rs:98` 那句"构建侧待补"。这次不是"补个注释"，而是**把它做完并验证到底**：
> 代码 → 自检 → 门禁 → 重构建 ISO → **在 guest 里看到等宽字体真的被加载**。

## 一、问题（此前一直存在，但 ISO 里看不出来）

`aether-compositor/src/text.rs:99` 的等宽候选表第一项是
`/usr/share/fonts/truetype/aether/NotoSansMonoCJKsc-Regular.otf`，
而构建期的 `scripts/mkfont.py` **只产出正文两个字重**（`NotoSansSC-Regular/Bold.otf`）——
候选表里的三个等宽名字**一个都不存在** → 终端只能**逐字回退**到正文字体（非等宽）。

失败方式是"安静的"：构建成功、串口只有一行
`无可用字体，尝试过 ["…NotoSansMonoCJKsc-Regular.otf", …]` 就过去了 ——
**不报错、不影响启动**，只有真去用终端才看得出不是等宽。所以它需要一条**本机就能跑**的判据。

## 二、改法（`scripts/mkfont.py`）

| 点 | 做法 | 理由 |
|---|---|---|
| 产物名 | `NotoSansMonoCJKsc-Regular.otf` | **必须与 `text.rs:99` 逐字一致**（改错就"构建成功、字体永远加载不到"） |
| 字符集 | **只要 ASCII + 制表/符号（136 字）**，**故意不带汉字** | `text.rs:358` 的判定是 `mono && self.mono.has_glyph(ch)` —— **缺字形会逐字回退**到正文字体。塞 6763 个汉字纯属浪费 ISO 体积（实测**只差 47 KB**） |
| 源字体缺失 | 只警告、**不阻塞构建** | 正文两个字重才是必需的（没有它们会退回 wqy 伪粗体）；等宽缺失只是"终端非等宽"的质量降级 |
| OTF 处理 | `subset_one(face=None)` 不传 `--font-number` | 等宽源是**单体 OTF**，不是 TTC |
| 判据 | `mkfont.py --selftest`（9 项）进了 `gates.py` | **不需要 fontTools、不需要源字体** —— 构建机常常不可用，这条本机就能跑（门禁 33 → **34 项**） |

## 三、验证（四层，逐层加硬）

1. **自检**（本机，不需要字体）：`python3 scripts/mkfont.py --selftest` → 9 项全过，含命名契约与"等宽字符集故意不含汉字"。
2. **构建机上真跑**（42.9 MB ISO 的构建链内）：
   ```
   [mkfont] NotoSansSC-Regular.otf  2908 KB  字形 14010  可映射字符 7548  轮廓 CFF
   [mkfont] NotoSansSC-Bold.otf  2919 KB  字形 14010  可映射字符 7548  轮廓 CFF
   [mkfont] NotoSansMonoCJKsc-Regular.otf  46 KB  （ASCII + 制表/符号 136 字；汉字靠逐字回退）
   [mkfont] 完成：正文 2 个字重合计 5.69 MB + 等宽 47 KB
   ```
3. **重构建 ISO**：`RESULT=PASS` · `42,991,616` 字节 · `sha256=eea68da9e4a9c7c58558c488b8c3f0192d82c0b550effde1d5cb194e58211e69`
   · offset 510 = **`55aa`**（isohybrid 仍在）。
4. **guest 里实测**（VirtualBox 从新 ISO 冷启动，串口为证）：
   ```
   aether-compositor: 字体已加载 /usr/share/fonts/truetype/aether/NotoSansSC-Regular.otf
   aether-compositor: 字体已加载 /usr/share/fonts/truetype/aether/NotoSansSC-Bold.otf
   aether-compositor: 字体已加载 /usr/share/fonts/truetype/aether/NotoSansMonoCJKsc-Regular.otf   ← 新
   aether-ops: 巡检#1 up=2s mem=85/970MB 服务=aetherd=✓ compositor=✓ getty=✓ network=✓ ops=✓
   ```
   **"无可用字体"这一行彻底消失** ✓（旧 ISO 每次启动都有）。

> 反面教训（顺手记下）：我一开始想在 ISO 字节里 `grep` 字体文件名来验证，结果是 **0 次** ——

## 四、过程中的一个真陷阱（改了 `Cargo.lock` 之后必踩）

这次重构建先 **失败**（`rc=101`），日志里刷屏：

```
warning: spurious network error: [6] Could not resolve hostname (Could not resolve host: index.crates.io)
error: failed to select a version for the requirement `rustls = "^0.23.19"` (locked to 0.23.46)
  ... required by package `ureq v2.12.1` ... of package `aetherd v0.1.0`
```

原因：CVE 修复把 `rustls` 从 0.23.43 提到 **0.23.46**，而**构建机的 cargo 离线缓存里只有 0.23.43**；
构建机现在走 host-only（**没有外网**），于是解析失败。

修法（不用联网，也不用改网络）：从**宿主**的 cargo 缓存里把两样东西 SFTP 上去 ——
① `rustls-0.23.46.crate`；② **索引缓存** `.cache/ru/st/rustls`
（**只传 crate 不够**，`--offline` 仍会"选不出版本"）。传完 `cargo build --workspace --offline --locked`
→ `Finished dev profile in 58.61s` ✓。

> 注意：宿主用的是 rsproxy 镜像（`index/rsproxy.cn-*`），构建机是 `index.crates.io-*`，
> 目录名不同但**索引 JSON 内容相同**、cargo 主版本一致（1.98），所以直接覆盖可用
> （覆盖前先 `cp` 备份成 `.bak`）。
