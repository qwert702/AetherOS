## 二、根因分析

修前的 workflow 把所有门禁塞进一个 job：

```text
gates.py --online
  ├─ cargo build / cargo test
  ├─ e2e（无界面）
  ├─ 像素回归（依赖字体/渲染环境）
  ├─ 布局几何（依赖字体/渲染环境）
  ├─ 性能门禁（依赖稳定帧时间）
  └─ ...
```

这条链路在开发机（有 `target/` 缓存、字体、稳定环境）能跑，但在 GitHub 托管 runner 上不成立：

1. **字体与显示环境不稳定**：像素/布局门禁需要仓库里没有入库的字体产物（`platform/overlay/usr/` 被 `.gitignore` 忽略），干净 checkout 下可能退化或失败；
2. **性能门禁本身受 runner 负载影响**，不适合作为每次 push 的硬门禁；
3. **单 job 串行**：前面的全量门禁一红，后面的 Linux 专属 `cargo test` 永远不执行——这正是 CI 本来要补的洞；
4. **Linux 构建依赖未显式安装**：`minifb` 需要 X11/xkbcommon 开发库，Ubuntu runner 不保证预装。

## 三、修复方案

### 1. `scripts/gates.py` 新增 `--ci`

`--ci` 只跑：

- `cargo build --workspace --all-targets --locked`
- `cargo test --workspace --locked`
- 全部快速门禁（文档、站点、链接、依赖声明、纯函数自检）

不跑依赖字体/显示/计时的像素、布局、性能门禁；不静默跳过——在文档中写明由构建机执行。

同时新增 `--log-dir`，把每一步完整输出落盘，便于 CI 失败时上传 artifact/排查。

### 2. `.github/workflows/ci.yml` 拆成两个 job

| Job | 平台 | 内容 |
|---|---|---|
| `fast` | ubuntu + windows | `python scripts/gates.py --fast` |
| `test` | ubuntu + windows | `cargo build --workspace --all-targets --locked` + `cargo test --workspace --locked` |

Ubuntu 的 `test` job 会安装 `libx11-dev`、`libxkbcommon-dev`、`libxkbcommon-x11-dev`、`libxcb1-dev`、`libwayland-dev`，并真实执行 `cfg(unix)` / `cfg(target_os = "linux")` 分支。

### 3. 全量门禁的归属

像素、布局、性能门禁仍在构建机/自托管 runner 上跑，命令：

```bash
python scripts/gates.py          # 全量 41 项
```

它们不再阻塞每次 push，但仍保留在发布前的手工/构建机验收清单里。

## 六、第一次 GitHub 运行（run #75）暴露的真实问题

推送 CI 修复后，run #75 仍然失败；它把“以前没跑过”的问题暴露了出来：

| job | 失败点 | 根因 | 修复 |
|---|---|---|---|
| 快速门禁（ubuntu/windows） | `gates.py --fast` 退出 1 | 归档走查图门禁需要 `target/debug/aether-compositor`，干净 checkout 没有构建产物 | `gates.py` 在无二进制时**显式跳过并打印原因**；`--ci` 也跳过像素门禁 |
| 编译与测试（ubuntu） | `cargo build` 退出 101 | `libc::ioctl` 的 request 参数在 glibc 上是 `u64`，两处常量是 `i32`：`input.rs` 的 `EVIOCGABS_*`、`aether-init/autoinstall.rs` 的 `CDROM_DRIVE_STATUS` | 调用处改为 `as _`，让编译器按目标 ABI 推断（musl/glibc 都通过 `cargo check`） |
| 编译与测试（windows） | `cargo test` 退出 1 | CI 默认用 MSVC，而仓库的 Windows 路径是 GNU（`.cargo/config.toml` 的 rust-lld + 自包含 mingw） | workflow 在 Windows 上安装并使用 `stable-x86_64-pc-windows-gnu`，并设 `RUSTUP_TOOLCHAIN` |
| 本机 Linux 目标 | 拆分后 14 个可见性错误 | 模块拆分后 `Installer` 字段、`run_fbdev`、`snapshot` 对子模块不可见 | 改为 `pub(crate)`；`cargo check --target x86_64-unknown-linux-gnu` 六个 crate 全绿 |

以上修复后本地验证：

- `cargo test --workspace --offline --locked`（GNU 工具链）：**793 项全绿**
- `cargo check --all-targets --target x86_64-unknown-linux-gnu`：compositor / init / ops / install / ipc / shell **0 error 0 warning**
- `python scripts/gates.py --fast`（有构建产物）：28/28；干净 checkout 下归档门禁跳过（27 项）
