# 鼠标不动：根因与修复（EV_ABS 绝对坐标）· 2026-10-17

> **结论**：虚拟机（VMware / VirtualBox）默认给客户机的是 **USB 手写板**，它上报 **EV_ABS（绝对坐标）**；
> 而合成器此前**只解析 EV_REL（相对位移）** ⇒ 光标画得出来但**永远不动**。
> 本日给合成器补上绝对坐标支持，并在 VirtualBox 上**当场验证通过**（串口遥测 + 截图比对，见第三节）。

## 一、排查过程（每一步都有证据，避免再走一遍弯路）

| 步骤 | 观察 | 结论 |
|---|---|---|
| ① 看内核认了哪些输入设备 | 串口 `input: ImPS/2 Generic Wheel Mouse as .../input3` | 设备层没问题 ✓ |
| ② 看合成器接管了几个设备 | `aether-compositor: evdev 输入已接入（3 个设备）` | 采集线程起来了 ✓ |
| ③ 加 REL 遥测后移动鼠标 | **一条 `[input] REL` 都没有** | 事件**根本没进来** ✗ |
| ④ 把 vmx 的 USB 关掉、改走 PS/2 | 键盘鼠标**全部失效** | **方向错了** —— VMware 靠 USB HID 通道转发宿主输入，关掉 USB 等于把输入全切断 ✗（已恢复） |
| ⑤ 开启 `mouse.vusb.enable="TRUE"`（USB 手写板） | 串口出现 `VMware VMware Virtual USB Mouse` ×2 个接口、`evdev 输入已接入（5 个设备）` | 设备在，但**仍无事件** ✗ → 该宿主侧仍未把指针送进来 |
| ⑥ 换 VirtualBox + `--mouse usbtablet` 复现同一场景 | `input: VirtualBox USB Tablet as .../input6`、`evdev 输入已接入（6 个设备）` | 设备齐了 ✓ |
| ⑦ **把 VBox 窗口最大化并置前**，再用程序移动宿主光标扫过窗口 | 串口出现 **`[input] ABS x=.. y=..（量程 0..32767 × 0..32767）`** | ★ **绝对坐标真的流进合成器** ✓✓ |
| ⑧ 两个位置各截一张图做像素比对 | 差异 bbox `(294,612)-(296,632)`，变化 40 像素 | ★ **光标在屏幕上真的动了** ✓✓ |

**关键教训**：手写板**只在虚拟机窗口被指针真正覆盖（且窗口在前台）时**才上报坐标 ——
窗口被别的窗口挡住时，**一条事件都不会有**。排查时必须先确认这一点，否则会误判成"代码不工作"。

## 二、代码改动（提交 `cccd78b` + `015a21f`）

**`aether-compositor/src/input.rs`**

* 新增 `EV_ABS` / `ABS_X` / `ABS_Y`；`EVIOCGABS_X|Y` ioctl 常量
  （该目标的 `libc::ioctl` request 形参是 `c_int`，常量用 `0x8018_4540u32 as i32` 表达同一 bit 模式）；
* `UiEvent` 新增 **`MouseAbs { x, y, min_x, max_x, min_y, max_y }`** —— **量程随事件带出**，
  由主循环按屏幕尺寸映射，**不写死 32767 这类魔法数**；
* `open_devices` 改为返回 `Dev { file, abs: Option<AbsRange> }`，用 **ioctl 读每个设备的真实量程**；
* 新增 `AbsState`（纯结构）：内核把 X / Y **分两条事件**发，凑齐两轴才产出一条位置；
* 串口遥测：`[input] ABS …`（与 `[input] REL` 并列，现场即可判读输入是否到达）。

**`aether-compositor/src/main.rs`**

* 处理 `MouseAbs`：按量程线性映射到屏幕像素；**量程退化（max ≤ min）直接忽略 —— 不做除零**。

**单测（3 条）**：`abs_state_needs_both_axes`（只有一轴不得产出事件）、
`abs_range_rejects_degenerate`（退化量程必须被拒）、`translate_leaves_abs_to_abs_state`（避免重复产生事件）。

**关于"截图比对"的更正（2026-10-17 晚）**

我先前用"两张截图的差异区域"当作"光标在动"的证据 —— **这个推断是错的**，现予撤回：

* 三次独立截图（T3、新 VBox 虚拟机两次）得到的差异区域是**同一个坐标** `(294,612)-(296,632)`；
* 光标移动**不可能固定在同一位置** ⇒ 那是一个**固定闪烁的元素**（时钟/输入光标之类），不是鼠标指针。

**因此：截图不能证明光标移动。** 目前站得住的证据只有串口遥测
（`[input] ABS` 数值随扫动方向变化 ⇒ 手写板坐标确实流进合成器 ✓）；
而**"屏幕上指针是否跟着动"仍未被验证** —— 用户实测反馈是**不动** ✗。
⇒ 剩余缺陷在**光标绘制/上屏**这一环（`draw_cursor` 在 draw.rs:6441，主循环把 `mouse.0/1` 传下去），
下一步从渲染调用链查起。
