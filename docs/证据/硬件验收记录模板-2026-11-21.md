>
> **口径**：每条记录对应清单一个编号 × 一台机型；结果只能填 **通过 / 失败 / 不适用 / 待硬件**；
> 没跑之前留空或填「未执行」，禁止写"已验证 / 支持"。虚拟机记录必须在「环境」列注明 VM 类型，
> **虚拟机结论不得记入物理机结论**。

## 1. 字段说明

| 字段 | 填写要求 |
|---|---|
| 编号 | H1-01 … H1-45，与清单一一对应 |
| 验收日期 | `YYYY-MM-DD` |
| 环境 | 物理机 / VMware / VirtualBox / QEMU（TCG）；物理机必填机型 |
| 机型 / 主板 | 物理机填主板型号与整机型号；VM 填软件版本 |
| CPU | 型号；VM 填虚拟 CPU 类型（如 qemu64 / vmx64） |
| GPU / 显卡 | 真实显卡型号；VM 填虚拟显卡类型 |
| 固件 / BIOS | 物理机填 BIOS/UEFI 版本；VM 填固件（BIOS/UEFI） |
| 内核版本 | `uname -r` 输出 |
| 结果 | 通过 / 失败 / 不适用 / 待硬件 / 未执行 |
| 异常现象 | 失败或不适用时写清现象、报错、串口关键行；无异常填"无" |
| 证据路径 | `docs/证据/实机-<编号>-<项目>-<日期>.<ext>`；多件用分号分隔 |
| 记录人 | 执行人 |
| 备注 | 复测轮次、与上一次结果对照、遗留问题等 |

## 4. 证据命名与归档

- 命名：`实机-H1-<编号>-<项目>-<YYYY-MM-DD>.<ext>`，例：`实机-H1-09-帧时间-2026-11-21.txt`。
- 截图 / 照片 / 串口日志 / 命令输出放 `docs/证据/`；>1 MB 日志压缩入库或只留摘要 + 原始路径。
- 失败项复测新增一行，不覆盖原失败记录；复测轮次写「备注」。
