# AetherOS 未实现功能清单 · 2026-09-27

起因：少爷反馈"文件不能打开"。核查后确认——**那不是 bug，是功能没做**：文件管理器此前是纯视觉演示
（20 个假图标、假侧栏、假状态栏），点击落到鼠标处理链的 `else` 分支，什么都不做。

本文档盘点**所有"看着能用、实际不能用"的交互**，标注严重级别与实现成本，供排期。

> 严重级别按**用户预期落差**定，不按实现难度：
> - **P1** 用户会立刻踩到，且没有替代路径
> - **P2** 用户会尝试，但影响有限或有绕法
> - **P3** 演示性内容，短期不做也不影响使用

---

## 一、本轮已实现（2026-09-27）

| 功能 | 说明 |
|---|---|
| 文件列表接真实目录 | 读 `$HOME`（Linux）/ `%USERPROFILE%`（Windows），目录在前、按名排序，隐藏 `.` 开头的项 |
| 文件 / 文件夹区分图标 | 文件夹蓝色带页签，文件冷白带折角与文字线，扫一眼能分辨 |
| 单击选中 | 选中项用强调色底 + 描边，与 hover 明确区分 |
| 再次点击打开 | 目录 → 进入；文本文件 → 预览窗口 |
| 返回上级目录 | 侧栏顶部"← 上级目录"；已在根时自动隐藏 |
| 文本文件预览 | 行号栏 + 内容，限 64 KB / 400 行，底部显示完整路径 |
| 读失败可见 | 目录读不了、文件是二进制、文件过大 —— 都在界面上说明原因，不是空白 |
| 窗口标题跟随目录 | 标题栏显示当前目录名（如 `cbn`），不再是写死的"文件" |

**设计取舍记录**：
- 用"二次点击打开"而不是双击 —— 双击要引入计时器，会让**单击延迟生效**，手感更差。
- 预览不换行 —— 行号必须与源文件一一对应，换行会打乱这个关系。
- 二进制文件不 `lossy` 转换 —— 糊一屏乱码不如直接说"这是二进制文件"。

## 二、仍未实现

### P1 · 没有替代路径

| # | 功能 | 现状 | 成本 |
|---|---|---|---|
| 1 | **窗口关闭 / 最小化 / 最大化** | 红绿灯**只画不响应**。开了 8 个窗口后只能靠布局键重排，关不掉 | 中 |
| 2 | **文件列表滚动** | 条目超过窗口容量时，后面的**完全看不到**（状态栏会提示"显示 N"，但没有翻页手段） | 中 |
| 3 | **侧栏项** | "文档/图片/音乐/项目"是**静态假数据**，点击无反应，也不反映真实目录 | 中 |

> 第 1 条最刺眼：窗口开满之后没有任何关闭手段，用户会立刻卡住。

| # | 功能 | 现状 | 成本 |

| 4 | 音乐播放控件 | 进度条、播放/暂停、上一首/下一首**全是画上去的**，点击无反应 | 高（需音频后端） |

| 7 | 右键菜单 | 无上下文菜单 | 中 |
| 8 | 路径导航 | 只有"上级"，没有面包屑、没有地址栏、不能直接跳转 | 中 |
| 9 | 预览窗口滚动 | 只看得到前 N 行，长文件看不全 | 低 |
| 10 | 搜索 | 点搜索胶囊只弹一句提示，没有实际检索 | 中 |
| 11 | 文件多选 | 无 Ctrl / Shift 多选 | 低 |
| 12 | 预览大文件 | 超过 64 KB 直接拒绝预览 | 中（需分页读） |

## 三、给排期的建议

按"用户会不会卡住"排序，而不是按功能听起来多重要：

1. **窗口关闭**（#1）—— 唯一一个会让用户彻底卡死的缺失
2. **文件列表滚动**（#2）—— 家目录里 76 个条目只显示 8 个，这是最常见的日常操作
3. **侧栏接真实路径**（#3）—— 顺手能把 #8 的路径导航一起解决
4. 音乐控件（#4）—— 工作量最大（音频后端），但它对"AI-First OS"的核心叙事贡献最小，建议靠后

**关于写操作（#15）**：文件管理器目前是纯只读的。加删除/重命名意味着引入新的权限等级
（L2 敏感写），需要走 `Gate` 闸门与确认卡片 —— 这是**权限模型的问题，不是 UI 的问题**，
应该和 `docs/ai-permissions.md` 一起设计，不要顺手加。
