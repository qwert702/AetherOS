# AetherOS 功能缺口与增强规划 · 2026-10-02

本文档回答一个问题：**"这个系统还缺什么？"** —— 并给出**可验收**的清单，供排期。

它不同于 `docs/roadmap.md`（那是我方路线图，按版本推进），本文档按**用户预期落差**排，
并且**每一条都附代码证据**（`文件:行号`）或明确标注"未验证"。

---

## 0. 评估方法与结论边界

**方法**：在仓库里实际检索代码（不是凭印象），逐条确认"有没有"；能上真机的以真机为准。

**分级口径**（按用户预期落差，不按实现难度）：

| 级别 | 含义 |
|---|---|
| **P0** | 用户**第一天**就会碰到，且**没有替代路径** —— 缺了它系统"不像系统" |
| **P1** | 用户会尝试，影响体验但能绕开；或系统能力明显不全 |
| **P2** | 工程质量与长期可维护性（用户不直接看见，但决定项目能不能长大） |

**结论边界（重要）**：
- 本文所有"缺失"结论都基于**当前仓库代码**。若某能力由内核/Buildroot 外部提供而我没检索到，
  我会在附录 B 明确标注"未验证"。
- **不做"看着很酷但没后端"的条目** —— 见 §6 明确不做清单。

## 1. 结论摘要（一页看完）

## 2. P0：硬伤（用户第一天就会碰到）

### 2.1 电源操作：关机 / 重启 / 注销

**现象**：桌面、控制中心、设置里**都没有**关机/重启入口。

**证据**：全仓库检索 `poweroff|reboot|Shutdown|关机|重启系统`，**只命中一句提示文案** ——
`aether-compositor/src/draw.rs:3723`（"正在写入磁盘，请勿关机…"）。
即：系统知道"关机"这个概念，但没有实现它。

**影响**：
- 用户无法正常关机，只能按虚拟机电源键 / 长按物理电源键（等于**硬断电**，可能损坏文件系统）
- 装盘向导完成后没有"重启进入系统"的引导
- 演示给别人看时，"怎么关机？"这个问题无法回答

**验收标准**（可测）：
1. 控制中心与设置里出现「关机 / 重启 / 注销」三个入口
2. 点击后**先二次确认**（与 AI 的确认卡片同一套交互，危险动作一律不例外）
3. 确认后：aether-init 收到 power 动作 → `sync()` → `reboot(RB_POWER_OFF)`，
   **5 秒内**断电（无 GUI 时也能从串口看到关机日志）
4. **审计留痕**：谁、何时、执行了哪种电源动作（与 `perm.rs` 的审计同一格式）
5. 关机前给各服务发送停止信号并等待（不能直接拔电式 `exit`）

**成本**：小（半天级）。

**实现要点**：
- IPC：新增 `Request::SystemPower { action: PowerAction }`，
  或复用 `ServiceControl` + 保留单元名 `power` —— 前者语义更清晰，后者改动更小。
- 鉴权：**必须**要求已注册 UI 通道（与 `ServiceControl` 同规矩），且**必须**带确认令牌 ——
  "关机"是不可逆动作，不能由未确认连接触发。
- 执行：`aether-init` 落 `sync()` + `reboot(2)`；合成器只发意图（不直接碰系统）。
- 注销：当前无多用户，注销可定义为"重启合成器"（先有 §2.3 才谈得上真注销）。

**风险**：直接 poweroff 会丢未落盘数据 → 必须先 `sync` + 通知服务停止。

---

### 2.2 声音：完全没有音频栈

**现象**：系统没有任何声音 —— 无提示音、无音量控制、播放器无声。

**证据**：`platform/br2-external` 检索 `alsa|alsa-lib|pulseaudio|pipewire` → **零命中**。
即镜像里连音频库都没打包。

**影响**：
- 确认卡片出现、AI 回复完成、操作失败 —— 全都**没有声音反馈**（视觉反馈不能替代）
- 「音乐」应用是无声的
- 用户会以为"声音坏了"，而不是"没做"

**验收标准**：
1. 镜像含 ALSA 用户态（`BR2_PACKAGE_ALSA_LIB` + `alsa-utils`）
2. 合成器能播放**一个**提示音（确认卡片弹出 / AI 回复完成时），可开关
3. 控制中心出现**真实**音量滑块：读/写 mixer，显示真实百分比
4. **没有音频设备时如实显示**「无音频设备」——**不允许**画一个假滑块
   （这是本项目已经确立的规矩：不做假控件）

**成本**：中。

**实现要点**：
- 播放：优先 libasound（`snd_pcm_writei`）播放内嵌 WAV；不引入完整混音器
- 权限：`/dev/snd/*` 归 `audio` 组，合成器与 aetherd 的账户要入组
- **VMware 虚拟机可能没有虚拟声卡** → §2.2 的验收标准 4 是必须项，不是可选项

**风险**：VMware 下无设备会让"音量滑块"看起来像坏了 → 必须走"如实显示"分支。

---

### 2.3 登录 / 锁屏 / 用户账户

**现象**：开机直接进桌面，没有登录界面，也没有锁屏。

**证据**：Rust 用户态检索 `登录|login|password|锁屏|lock_screen` →
只命中 `aether-init/src/unit.rs:24` 的注释（"终端登录（tty1）"）与两处**安全测试用例**
（`aetherd/src/tools.rs:1043` 屏蔽 `/etc/shadow`、`aetherd/src/apps.rs:147` 拒绝符号链接
—— 这两处是**做得好**的地方，说明权限模型已经在防这类路径）。

**影响**：
- 没有隐私边界：离开座位 = 别人可以直接用
- 多用户不成立（而"多用户"是"系统"的定义性能力之一）
- AI 的权限模型很强，但**没有"当前是谁"**这个前提

**验收标准**：
1. 开机出现登录界面；无图形时 tty1 有登录提示
2. 密码校验走 PAM 或自研的 `crypt` 校验（**不允许**明文比较）
3. `Super+L` 锁屏；锁屏后必须重新验证才能回桌面
4. 首次登录向导（语言/时区/主题）——见 §5.8
5. 失败次数限流（防暴力破解）

**成本**：中（账户模型是主要工作量，不是界面）。

**实现要点**：先定**单用户 + 密码**最小模型（不做组权限/家目录隔离），
把"多用户"留到 M3；锁屏与登录共用同一套验证函数。

---

### 2.4 设置"改不了"：大多数页面是只读的

**现象**：设置中心 8 页里，真正能**改系统**的只有刚做的两个"重启服务"动作。

**证据**：
- `aether-compositor/src/settings.rs` 的 `SettingsHit` 只覆盖：
  切页 / 24 小时制 / 显示秒 / 时区偏移 / 输入法默认 / 深色模式 / 鼠标速度 /
  打开应用 / 重启服务 —— **全是合成器本地偏好**，不写系统配置
- 「网络」页读的是 `/proc/net/route`、`/proc/net/fib_trie`、`/etc/resolv.conf`
  （`aether-compositor/src/net.rs:173-186`）—— **只读展示**

**影响**：用户带着"来改设置"的预期进来，却发现**改不了任何东西**。
这比"没有设置"更伤 —— 有入口但无能力。

**验收标准**（按优先级）：
1. **壁纸**：可选内置壁纸 + 纯色，**持久化**，重启后保持
2. **界面缩放**：字号/控件缩放 3 档（100/125/150%），立即生效并持久化
3. **网络写入**：静态 IP / DNS 可改（写 `/etc/resolv.conf` 与接口配置），
   改完显示"已应用/失败原因"，失败**必须**给出原因
4. **默认应用**：文件/文本预览的默认打开方式可改
5. 每一项都有**"恢复默认"**（用户改坏了能回去）

**成本**：中。

**实现要点**：先做**不碰系统的**（壁纸、缩放、默认应用）——纯本地状态，成本低、见效快；
网络写入涉及 aetherd 鉴权，单独排期。

## 3. P1：系统能力层（缺了就不像完整 OS）

| # | 事项 | 现状与证据 | 影响 | 成本 |
|---|---|---|---|---|
| 3.1 | **更新机制** | 7 个 crate 无 updater；`aether-install` 是**装盘**向导 | 装好之后**无法升级**；对"还活着的项目"是命脉 | 中大 |
| 3.2 | **通知中心** | 只有 toast（合成器本地状态） | 错过就没了；无法回看"刚才提示了什么" | 小 |
| 3.3 | **NTP 对时 + 时区写入** | 时钟是本地偏移（`settings.rs` 的 `tz_offset_min`） | 时间会漂；时区改了系统时间没变 | 小 |
| 3.4 | **无障碍基础项** | 全仓库无相关代码 | 字号/对比度/动画不可调 | 中 |
| 3.5 | **多语言（i18n）** | 界面文案硬编码中文；站点已有 `en/` 页 | 非中文用户体验门槛高 | 中 |
| 3.6 | **电源管理 / 息屏** | 无空闲熄屏、无休眠 | 长时间开着屏（虚拟机无所谓，实机费电） | 小 |
| 3.7 | **打印 / 蓝牙 / USB 热插拔** | 无相关代码 | 外设接上没反应 | 大 |
| 3.8 | **多显示器 / HiDPI / 旋转** | 渲染走 `fbdev.rs` / `vt.rs` 单屏路径 | 外接屏无法用 | 大 |

**3.1 补充**：应用安装其实**已经有了** —— `aetherd/src/apps.rs`（清单校验、目录安装、
卸载进回收站、递归依赖闭包预检、拦截 glibc 家族、库名路径穿越防护），
打包器与格式见 `docs/APP-PACKAGES.md`。所以"更新机制"缺的是**系统自身**的更新
（A/B 分区或差分），而不是应用安装。

## 4. P2：工程质量（用户看不见，但决定能不能长大）

### 4.1 自动 e2e：现在每个功能都要人工点一次

**现象**：今天实现的「重启网络服务」，我**只能验证到编译与单测**，
真机 toast 是否出现**无法自动验证**（客户机没装 VMware Tools，点不进去）。

**证据**：仓库里**已经有** QEMU/QMP 工具 ——
`scripts/qmp-slow-click.py`、`scripts/qemu-shot.py`、`scripts/qmp-verify.py`、
`scripts/e2e-permission-confirm.py`。缺的是**把它们串成一条断言链**。

**验收标准**：
1. `python scripts/e2e-ui-actions.py` 能：启动 QEMU → 点设置 → 点「重启网络服务」→
   截图 → 断言 toast 出现 aetherd 的 ack 文案 → 退出码 0
2. 至少覆盖：开/关窗口、设置各页、两个服务动作、确认卡片"允许/拒绝"两条路径
3. 纳入提交前检查清单

**成本**：中。**这是长期收益最大的一条** —— 否则"没人点 = 没验证"。

### 4.2 性能门禁

合成器已能跑到 12 万帧以上，但**帧预算没进门禁**。建议：`--bench 300` 输出
平均/最差帧时间，CI 阈值（如 P99 < 16 ms），超标即失败。

### 4.3 硬件矩阵

目前只确认 x86_64 + Buildroot 软件渲染。**未验证**：其它平台、真实显卡、
真实声卡、真实网卡。建议至少补一张"实机验证清单"（见附录 B）。

## 5. 建议新增的功能（"再添加一点"）

以下不是补缺口，是**让系统更像一个成品**的增强项。选择标准：**契合本系统"AI 中枢 +
原创 Rust 用户态 + 强权限模型"的身份**，且不做没有后端的假功能。

| # | 功能 | 为什么契合 | 用户价值 | 成本 |
|---|---|---|---|---|
| 5.1 | **AI 动作撤销（Undo）** | AI 能改窗口/布局/开应用，是它最大的卖点，也是最容易"改错"的地方 | 一键撤回 AI 的上一步动作，敢用 | 小 |
| 5.2 | **AI 行为时间线** | 审计日志已在写（`/var/log/aether/aether-audit.log`，解析见 `audit.rs`） | 设置里看"AI 到底做过什么"，可搜索可导出 | 小 |
| 5.3 | **权限策略编辑器** | 权限模型（L0-L3 + 确认令牌 + 审计）是项目最强的一块 | 每个工具一行：每次询问 / 允许 / 禁止 | 中 |
| 5.4 | **窗口贴边分屏（Aero Snap）+ 虚拟桌面** | 用户明确要求"像 Windows/macOS" | Windows 用户的肌肉记忆；macOS 的 Spaces | 中 |
| 5.5 | **命令面板（Ctrl+K，真搜索）** | 用户讨厌**假**搜索框 —— 那就做一个**真的** | 搜应用 / 设置项 / 文件（文件用已有的 `read_dir`） | 中 |
| 5.6 | **系统快照 / 回滚** | 装盘系统 + `aether-init/src/persist.rs` 已有状态持久化 | 折腾坏了能回滚（对"爱折腾"的用户是刚需） | 中大 |
| 5.7 | **一键诊断包** | `aether-ops` 已能生成诊断报告（`diagnose.rs`） | 出问题时导出 + 直接贴到 issue 模板 | 小 |
| 5.8 | **首次启动向导** | 新用户第一次进桌面 | 选语言/时区/主题/连网，降低上手门槛（对"要人气"直接有用） | 小 |
| 5.9 | **快捷键总览页** | 快捷键已散落在各处 | 设置里一页列全，且**逐条真实生效** | 小 |
| 5.10 | **性能 HUD（默认关）** | 显示**真实**帧时间/内存，不造假数据 | 折腾与排障用 | 小 |
| 5.11 | **应用商店界面** | 应用安装后端已完备（`apps.rs` + `mkapp.py`） | 让"装应用"这件事从命令行变成点一下 | 中 |
| 5.12 | **提示音主题 + 无障碍基础项** | 与 §2.2 声音配套 | 声音可关/可换；字号/高对比/减弱动画 | 中 |

**5.1 的实现要点**：给 AI 的每个"动作类"工具调用记录**逆操作**（关窗口 → 记窗口
原始几何与内容；改布局 → 记上一份布局），桌面维护一个**有界栈**（如 20 步），
`Ctrl+Z` 或 AI 指令"撤销"触发。**不做**"任意时间点回滚"（那是 §5.6 的事）。

## 6. 明确不做（划边界）

这一节和"要做什么"一样重要 —— 它防止项目长出"AI 味"：

| 不做 | 原因 |
|---|---|
| **假电池 / 假搜索 / 假进度条 / 假"已连接"** | 本项目已确立的规矩：宁可如实显示"无设备"，也不画一个假的。用户对假控件零容忍 |
| **没有后端的云同步 / 假账户** | 没有服务端就不做入口 |
| **装饰性动画堆砌** | 用户明确要求"不要 AI 味"；动效只服务于"状态变化可理解" |
| **未验证就宣称"已支持"** | 今天的教训：三次把"没验证"当成"已验证"。验收标准必须可测 |
| **为演示新造页面** | 动作要落在已有页面上（如"重启网络"落在「网络」页），不为了好看造空壳 |

## 7. 里程碑建议

| 里程碑 | 内容 | 完成判据 |
|---|---|---|
| **M1 · 像系统** | §2.1 电源操作、§2.2 声音、§2.4 设置能改（壁纸/缩放/默认应用）、§4.1 自动 e2e | 能正常关机；有提示音；壁纸能换且重启保持；e2e 脚本能点能断言 |
| **M2 · 敢用** | §5.1 AI 撤销、§5.3 权限策略编辑器、§5.2 时间线、§3.2 通知中心、§3.6 息屏 | 能撤回 AI 动作；能改权限策略且审计留痕；通知可回看 |
| **M3 · 长大** | §2.3 登录/锁屏、§3.1 更新机制、§5.11 应用商店、§3.4 无障碍、§3.5 i18n | 有登录界面；能升级系统；能一键装应用；能切换英文 |

**排序理由**：M1 解决"不像系统"，M2 解决"不敢用"（AI 权限与撤销），
M3 才是"能不能长大"（更新、分发、国际化）。§4.2/§4.3 贯穿全程。

## 8. 风险与依赖

| 风险 | 说明 | 缓解 |
|---|---|---|
| VMware 无音频/无声卡 | §2.2 在虚拟机里可能看不到效果 | 验收标准 4 强制"如实显示"分支；实机另测 |
| 电源动作不可逆 | 误触 = 丢数据 | 二次确认 + `sync()` + 服务停止等待 |
| 账户模型未定 | §2.3 的实现方式取决于"要不要多用户" | 先做单用户 + 密码；多用户留 M3 |
| 无自动 e2e | 新功能"没人点 = 没验证" | M1 必须完成 §4.1 |
| 实机硬件未知 | 只验证过虚拟机 | 建立实机验证清单（附录 B） |
