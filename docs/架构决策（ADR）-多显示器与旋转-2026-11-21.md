# ADR：多显示器与旋转（G4）

- 状态：**接受（设计评估阶段；当前不支持，不宣称支持）**
- 日期：2026-11-21
- 相关：`aether-compositor` 输出/坐标/布局/输入链路、G2（DRM/KMS 路线）、G3（damage tracking）、FEATURE-GAPS §3.8
- 对标：[后续发展计划（NEXT-PLAN）-2026-10-31](报告/后续发展计划（NEXT-PLAN）-2026-10-31.md) §4.2 G4、[功能缺口清单（FEATURE-GAPS）-2026-10-02](报告/功能缺口清单（FEATURE-GAPS）-2026-10-02.md) §3.8 / §9 #12、#39

## 背景

### 当前事实（代码可查）

- 合成器只绘制主输出。界面文案在 `aether-compositor/src/draw/settings.rs:736` 明确写出：
  > "Only the primary output is drawn; multi-monitor needs a layout/coordinate rework"
- 输出检测已有最小切片：能枚举输出，但除主输出外其余只参与息屏；多显示器与旋转**未做**，需布局/坐标体系改造，属重写级别（FEATURE-GAPS §3.8、§9 #39）。
- 输入走 evdev 绝对坐标（EV_ABS），当前直接映射到单缓冲坐标系，见 [鼠标绝对坐标（EV_ABS）-2026-10-17](证据/鼠标绝对坐标（EV_ABS）-2026-10-17.md)。
- 现有窗口布局引擎（两列/三列/独占/自由）、贴边吸附、虚拟桌面、命中表（HitTable）与 `--e2e click:x,y` 全部建立在**单屏幕矩形**假设上。

### 边界声明

**截至本 ADR 日期，AetherOS 不支持多显示器扩展桌面、不支持输出旋转、不支持 per-output 缩放。** 外接第二块屏时的预期行为是「如实只显示主输出」，而不是黑屏、错乱或把第二屏内容拉伸到主缓冲。任何对外材料、设置页文案、硬件矩阵在改造落地并真机验证前，都不得写成「已支持」。

## 需要改造的三块

### 1. 输出抽象与坐标体系

现状：帧缓冲宽高即屏幕宽高，全局只有一套矩形坐标。改造后需要：

- 每个输出独立描述符；
- 引入**全局逻辑坐标空间**：所有窗口、命中区、吸附边都落在逻辑坐标里；每个输出在逻辑空间中有自己的矩形与变换；
- 物理像素坐标 ↔ 逻辑坐标之间经 `scale` 与 `transform` 双向换算。

数据结构草案（字段命名以实现时为准，这里先定语义）：

```rust
/// 一个显示输出（connector）的描述符。
struct Output {
    /// 稳定输出 ID（复用底层 connector 编号或自增；重插后可识别）。
    id: OutputId,
    /// 逻辑位置：左上角在全局逻辑坐标中的位置（逻辑像素）。
    logical_pos: (i32, i32),
    /// 物理模式（像素）：宽 / 高 / 刷新率。
    mode: (u32, u32, u32),
    /// 逻辑缩放（1.0 / 1.25 / 1.5 …）；逻辑尺寸 = 物理尺寸 / scale。
    scale: f32,
    /// 旋转与翻转：Normal / Rotate90 / Rotate180 / Rotate270 / FlipX / FlipY。
    transform: OutputTransform,
    /// 是否启用；未启用的输出不进布局，也不接收输入映射。
    enabled: bool,
    /// 主输出：桌面壁棋盘、初始开窗、顶栏归属的默认输出。
    primary: bool,
}

/// 全局输出拓扑：逻辑矩形集合 + 命中查询。
struct OutputTopology {
    outputs: Vec<Output>,
    /// 物理设备坐标 → 所属输出 + 输出局部逻辑坐标。
    fn hit_test(&self, phys: (i32, i32)) -> Option<(OutputId, (f32, f32))>;
}
```

### 2. 布局引擎（扩展桌面拓扑）

现状：吸附边、最大化、两列/三列布局都按单屏宽高计算。改造点：

- 窗口锚定到所属输出；最大化/吸附只在**该输出的矩形**内生效，不跨输出拉伸；
- 虚拟桌面跨输出延续：同一虚拟桌面的窗口分布在各输出上，切换虚拟桌面时整体迁移；
- 输出热插拔：接入/拔出时重排窗口，拔出处的窗口回到剩余输出，不丢失活会话（沿用现有「关闭进托盘可撤销」的会话保留思路）；
- 跨输出拖拽属于后续增强，不在第一版范围内。

### 3. 输入映射

现状：EV_ABS 绝对坐标直接进单缓冲命中表。改造点：

- 设备坐标先经 `OutputTopology::hit_test` 判定落在哪个输出；
- 命中输出后，按该输出的 `transform` 做**逆变换**（旋转 90°/270° 时坐标轴要互换），再按 `scale` 换算到逻辑坐标，最后进命中表；
- 触摸/数位板类绝对设备的压力、轴映射随输出变换一并处理；相对设备（鼠标位移、滚轮）不做输出归属换算，只按焦点窗口路由；
- 输入设备与输出的绑定关系（哪块屏对应哪块触控）需要显式配置或默认就近，第一版先给默认规则。

## 迁移步骤（顺序即依赖顺序）

1. **输出枚举抽象**：只读枚举 connector/mode/scale/transform，不改变绘制与布局；现有单输出路径封装成「默认主输出」的特例；
2. **全局逻辑坐标**：布局引擎与命中表先迁到逻辑坐标，单输出下几何结果必须与现有像素基线一致；
3. **第二输出上屏**：在 KMS 路径（见 G2 ADR）支持多 connector 的前提下，把拓扑中第二个启用输出渲染出来；
4. **输入映射改造**：完成物理→输出→逻辑的换算链路，补真机点击断言；
5. **旋转与 per-output scale**：变换逆变换、文字与控件按输出缩放；
6. 每一步独立可回退；任一步在真机上无法验证，就停在该步并如实标注边界。

## 对现有像素门禁与测试的影响评估

- **57 档像素基线**：全部基于单缓冲、单分辨率。引入第二缓冲后，基线需要拆成「主输出基线 + 副输出基线」；单输出默认配置下现有断言必须保持零差异。
- **命中表 / `--e2e`**：`click:x,y` 当前语义是屏幕坐标；改造后语义变为全局逻辑坐标，e2e 脚本与查询返回值要同步更新，并补一条「跨输出点击」断言。
- **Windows 预览路径**：开发机无显示设备，预览与 `--shot` 必须保留单输出模拟模式；多输出几何用纯函数单测覆盖，不依赖真机。
- **缩放既有成果**：整体缩放 100/125/150% 已落地并像素验证（FEATURE-GAPS §2.4）；多输出改造不得回退单输出下的缩放几何，相关回归由现有布局检查与像素门禁兜住。

## 决策

**本轮（G4）只交付设计评估与输出抽象草案，不进入代码实现。实现以 G2 DRM/KMS 路线结论为前置：fbdev 单屏路径下做多输出改造收益有限且无法真实验证。**

分阶段路径：

- **阶段 0（本文）**：确定三块改造边界、数据结构草案与迁移顺序；
- **阶段 1**：输出枚举抽象 + 拓扑纯函数（不接上屏）；
- **阶段 2**：扩展桌面（双输出上屏 + 窗口锚定 + 输入映射）；
- **阶段 3**：旋转、per-output scale、热插拔；
- 跨输出拖拽、多套独立壁纸/状态栏不在本路线图承诺内，需要时另立 ADR。

## 理由

1. **前置依赖成立**：多 connector 枚举与多平面提交属于 KMS 能力；fbdev 仿真层不提供这套接口。先等 G2 spike 结论，避免在错误的地基上做重写级改造。
2. **单屏假设贯穿全栈**：布局、命中、输入、e2e、像素基线都按单矩形设计；不先抽象坐标体系就加第二输出，会把变换逻辑散落到绘制与交互各处。
3. **真机是硬验证条件**：多显示器结论只能在双输出物理机上判定；当前本机环境无显示设备（FEATURE-GAPS 附录 B 口径），设计先行、验证后置，与项目「未验证不宣称支持」的规矩一致。

## 后果

- 设置页与硬件矩阵继续如实标注「只绘制主输出」；现有 `settings.rs:736` 文案在阶段 2 完成并真机验证前不改；
- 阶段 1 的纯函数抽象可先行，不影响 fbdev 生产路径与门禁；
- 若 G2 回退 fbdev 路线，本 ADR 的阶段 2/3 顺延，不阻塞 M9 其他真机项。
