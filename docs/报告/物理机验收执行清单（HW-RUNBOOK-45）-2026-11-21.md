## 0. 口径（先读，避免把"写好"当成"验过"）

1. **清单写好 ≠ 验证过。** 本清单除架构上不适用项（H1-29）外，当前状态**全部为「未执行」**；在物理机上跑完并留下带日期、机型、结果、证据的记录之前，任何一项都不得写成"已验证 / 支持"。
2. **虚拟机验证 ≠ 物理机验证。** 仓库现有证据全部来自 VMware / VirtualBox / QEMU（TCG 软件模拟），只能证明软件路径在虚拟硬件上成立；真固件、真显卡、真声卡、真网卡、真外设、真实断电动作**没有任何物理机证据**。两者不得互相替代。
3. **每项必须留一行执行记录**：日期 / 机型（主板·CPU·GPU·BIOS/固件）/ 内核版本 / 结果（通过·失败·不适用）/ 异常现象 / 证据路径。记录模板见
   [`../证据/硬件验收记录模板-2026-11-21.md`](../证据/硬件验收记录模板-2026-11-21.md) 与
   [`../证据/硬件验收记录模板-2026-11-21.csv`](../证据/硬件验收记录模板-2026-11-21.csv)。
4. **没有硬件就写"待硬件"**：不得虚构机器型号、日期、结果；不允许用"应该可以 / 预计支持"替代实测结论。
5. **如实不支持也是一种通过**：对当前阶段有意不做的能力（多显示器、旋转、休眠、蓝牙配对、打印作业等），验收目标是"界面如实报告边界、不黑屏不乱画"，而不是要求功能可用。

## 3. 一次完整验收的执行顺序（建议 2 天节奏）

> 前提：至少两台不同机型的 x86_64 物理机（NEXT-PLAN M9 要求），一台测试 U 盘，USB-TTL 串口线，可联网环境。

### 第 1 天：引导、显示、输入、音频、基础外设（A–D、F）

1. **准备**：按母本 §1.1 确认 ISO isohybrid；写 U 盘；接串口抓日志。
2. **引导与安装**：H1-01 → H1-02 → H1-03 → H1-04 → H1-05。
3. **显示 / GPU**：H1-06 → H1-07 → H1-08 → H1-09 → H1-10 → H1-11 → H1-12。
4. **输入**：H1-13 → H1-14 → H1-15 → H1-16。
5. **音频**：H1-17 → H1-18 → H1-19 → H1-20。
6. **可移动介质**：H1-24 → H1-25 → H1-26。
7. 当日回填记录模板，导出当日串口日志与照片到 `docs/证据/`。

### 第 2 天：网络、电源、安全权限、更新回滚、自愈（E、G–J）

1. **网络**：H1-21 → H1-22 → H1-23。
2. **电源**：H1-27 → H1-28；H1-29 记为不适用并留边界记录。
3. **AI 与 IPC**：H1-30 → H1-31 → H1-32 → H1-33 → H1-34 → H1-35 → H1-36 → H1-37 → H1-38 → H1-39 → H1-40 → H1-41。
4. **更新 / 回滚**：H1-42（正常包 + 篡改/缺签名对照）→ H1-43。
5. **恢复 / 自愈**：H1-44 → H1-45（fsck 破坏测试放在最后，用专用测试盘）。
6. 两台机型分别跑完；交叉对照同一编号在两台机器上的结果。

## 4. 失败项归档规则

1. **失败不粉饰**：结果写"失败"，附现象、串口/命令输出、机型与内核版本；不得改成"通过 / 部分支持"。
2. **失败项三级归类**：
   - **代码缺陷**：能在仓库复现的，开缺陷记录并关联对应 crate / 源码位置；
   - **硬件兼容问题**：记录具体硬件型号、固件版本、现象，转入 H2 硬件矩阵对应行；
   - **环境/操作问题**：记录前置条件缺失或操作偏差，复测前先修正环境。
3. **复测要求**：同一失败项修复后必须在**同机型**上复测，并新增一行记录（不覆盖原失败行）；两次结果都留档。
4. **不适用项**：写明架构理由（有意不做 / 无后端），在 H2 矩阵落"不适用"态，不计入失败，也不计入"已验证支持"。
5. **证据与台账联动**：每回填一条物理机记录，同步更新 FEATURE-GAPS 附录 B「已验证结果」表与 NEXT-PLAN H1 进度；`docs/README.md` 索引由 Organizer 统一更新，本清单不擅自改动。
