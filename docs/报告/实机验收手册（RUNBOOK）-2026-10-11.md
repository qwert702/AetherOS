> **这份手册回答一个问题**：附录 B 那张"约 30 项实机验证清单"**具体怎么做**。
>
> 它和附录 B 的分工：附录 B 是**清单与口径**（要验什么、怎么算验过），

## 0. 谁能跑什么（先说清楚边界，免得白折腾）

| 环境 | 能跑 | 不能跑 |
|---|---|---|
| **Windows 开发机**（当前环境） | 全部单测、全部门禁、`--e2e` 无界面运行器、`--shot` 走查图、`--bench` 性能 | PID 1、ALSA、fbdev/显示、真机键鼠、块设备、装盘 |
| **Linux 构建机 / VM**（`scripts/setup-vm.ps1` 建的 Ubuntu） | 交叉编译、ISO 构建、QEMU 启停、QMP 键鼠注入与截图、权限链路 e2e（真实 IPC） | 真显卡、真实声卡、真外设（虚拟机没有） |
| **真机**（物理机 + U 盘） | 上面没有的一切：真实固件/显卡/声卡/网卡/外设、断电、装盘 | —（这一步必须在物理机上做） |

**在 Windows 上可以先跑掉的那一半**（这些命令本机实测可用）：

```bash
cargo test --workspace --offline            # 768 项单测
python scripts/gates.py                     # 全量门禁（约 15 分钟）
python scripts/e2e-ui-actions.py            # 行为 e2e（7 个场景，含双语通知）
python scripts/shot-diff.py verify          # 57 档像素逐字节回归
python scripts/bench-gate.py                # 性能门禁（P99 ≤ 33 ms）
```

## 1. 通用准备

### 1.1 制作可引导 U 盘（真机）

```bash
# ① 先确认 ISO 是 isohybrid（否则不能 dd 到盘引导）—— 首 512 字节必须有 0x55 0xAA 签名
python scripts/iso-components-check.py            # 组件是否都在镜像里
xxd -l 512 aetheros-0.1-amd64.iso | tail -2       # 末两字节应为 55 aa
# ② 写入 U 盘（把 <磁盘> 换成真实设备，**看清再敲**）
sudo dd if=aetheros-0.1-amd64.iso of=/dev/<磁盘> bs=4M status=progress conv=fsync
```

> ⚠️ **当前已发布的那版 ISO 没有经过 isohybrid**（见
> [`安全审计（SECURITY-AUDIT）-2026-10-02.md`](安全审计（SECURITY-AUDIT）-2026-10-02.md)
> 的 H-6）：装机不可用。必须先用本手册的姊妹篇
> [`镜像重建手册（ISO-REBUILD）-2026-10-11.md`](镜像重建手册（ISO-REBUILD）-2026-10-11.md)
> 重新构建。

### 1.2 抓日志（真机没有显示器也要能诊断）

```bash
# 内核/服务日志走串口；把 USB-TTL 接上后：
sudo picocom -b 115200 /dev/ttyUSB0            # 或任何串口工具
# 进桌面后，日志也在设备里：
less /var/log/aether/aether-audit.log          # AI 动作审计
ls /var/log/aether/                            # 服务日志（logtee 落盘）
aether-ops --bundle                            # 一键诊断包（§5.7）
```

## 4. 依赖的已知 CVE 核对（台账 #49）

**现象**：本机（Windows，离线）无法核对上游漏洞库，所以 `#49` 一直是 ⛔。
它需要的只是一台**能联网的机器**，跟硬件无关 —— 所以最容易销账。

```bash
# 方案 A（推荐）：cargo-audit
cargo install cargo-audit --locked
cargo audit                          # 对着 RustSec 库核对 Cargo.lock
cargo audit --json > docs/证据/CVE-审计-2026-10-11.json

# 方案 B：cargo-deny（更全，含许可证与重复依赖）
cargo install cargo-deny --locked
cargo deny check advisories

# 无网时的唯一诚实做法：导出依赖清单，人工对照（并**标注未核对上游库**）
cargo tree --workspace --edges normal > docs/证据/依赖清单-2026-10-11.txt
```

**记录什么**：直接依赖 8 个（serde / serde_json / anyhow / log / libc / fontdue /
minifb / ureq / ring）+ 传递依赖；每条列出"有/无已知 CVE + 编号 + 处置"。
**结果回填台账 #49**：无问题 → ✅ 并写明核对的日期与命令；有问题 → 列出并在 §9.2 记一次修复批次。
