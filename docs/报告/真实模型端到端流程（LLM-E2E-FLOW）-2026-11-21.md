## 一、测什么

脚本分五步，全部经真实链路，不 mock aetherd：

| # | 步骤 | 判据 |
|---|---|---|
| 1 | 网关探针：直连 `<base>/chat/completions` | HTTP 200，`choices[0].message.content` 非空 |
| 2 | IPC 握手：`ping` → `pong` | 收到 `pong` 帧 |
| 3 | IPC 对话：`chat` → 多条 `chat_chunk` 到 `done=true` | 拼回的回复正文非空；回传通道标识已记录 |
| 4 | 敏感上下文路由：含"密码/密钥"的对话 | 若回传通道，必须是 `local`（不得上云） |
| 5 | IPC 工具调用：`tool_call` `sys_probe/whoami`（L0 只读） | 收到 `tool_result`，`ok=true`，`output` 非空，工具名匹配 |

附加安全检查：**所有出站 / 入站 IPC 帧逐帧扫描，不得出现 API Key 原文**；
Key 只用于本机网关探针，不进 IPC、不写进日志与文档。

## 二、前置条件

1. **aetherd 已在运行**（guest 内 `aetherd serve`，或开发机调试实例），IPC 可达；
2. **OpenAI 兼容网关**可达：GLM / 自建网关 / 本地 Ollama 的 `/v1` 端点均可；
3. 网关凭据（Base URL、API Key、模型名）通过环境变量注入，**不写进仓库与文档**；
4. Python 3（脚本仅用标准库：`socket` / `urllib` / `json` / `argparse`）；
5. 被测 aetherd 的模型配置与脚本探针使用同一套端点（脚本本身不改 aetherd 配置）。

## 三、网络拓扑

```text
llm-e2e.py
  │ ① HTTPS 直连探针（Bearer Key，仅本机）
  └──▶ OpenAI 兼容网关  <base>/chat/completions

  │ ② NDJSON over IPC
  └──▶ aetherd（127.0.0.1:7311，QEMU hostfwd 可映射到 17311；Linux 也可走 Unix socket）
          └──▶ 本地 Ollama 或云端网关（router.rs 按任务特征与敏感度选通道）
```

- IPC 线协议：`aether-ipc/src/lib.rs`（`Request::Chat` / `Request::ToolCall` /
  `Response::ChatChunk` / `Response::ToolResult` / `Response::Pong`）；
- 路由判据：`aetherd/src/router.rs`（隐私关键词、敏感上下文、本地/云端可用性）；
- 端点协议：`aetherd/src/llm.rs`（OpenAI 兼容，非 2xx 带出服务器正文）。

## 四、环境变量

优先级：`AETHER_LLM_*` 优先，回落 aetherd 既有约定 `AETHER_*`。

| 变量 | 回落变量 | 说明 |
|---|---|---|
| `AETHER_LLM_BASE_URL` | `AETHER_API_BASE` | OpenAI 兼容 Base URL，如 `https://open.bigmodel.cn/api/paas/v4` |
| `AETHER_LLM_API_KEY` | `AETHER_API_KEY` | 网关 API Key（只在本机探针使用） |
| `AETHER_LLM_MODEL` | `AETHER_MODEL` | 模型名，缺省 `glm-4-flash` |

## 五、复跑命令

```bash
# 查看全部参数与退出码
python scripts/llm-e2e.py --help

# 配置凭据后复测（TCP，默认 127.0.0.1:7311）
export AETHER_LLM_BASE_URL="https://<网关>/v1"
export AETHER_LLM_API_KEY="<Key>"
export AETHER_LLM_MODEL="<模型名>"
python scripts/llm-e2e.py

# QEMU hostfwd 映射到 17311 时
python scripts/llm-e2e.py --host 127.0.0.1 --port 17311

# Linux guest 走 Unix socket
python scripts/llm-e2e.py --socket /run/aether/ipc.sock

# 只走 IPC、跳过直连网关探针（凭据存在性检查仍在）
python scripts/llm-e2e.py --skip-gateway-probe
```

## 六、退出码（被门禁 / CI 解析，不要随意改）

| 退出码 | 含义 |
|---|---|
| `0` | 全部断言 PASS |
| `1` | 断言失败：回复为空 / 工具未执行 / 通道越界 / 凭据泄露等 |
| `2` | **未执行**：未配置凭据（不是失败，是没有条件跑） |
| `3` | 连接失败：网关或 aetherd IPC 连不上 |

## 七、判据明细（PASS 需要全部满足）

1. 网关探针返回非空真实回复（不是空字符串、不是网关错误页）；
2. IPC 握手收到 `pong`；
3. 普通对话 `chat_chunk` 拼出非空正文；
4. 含隐私关键词的对话若回传通道，通道为 `local`；
5. `sys_probe/whoami` 返回 `ok=true` 且 `output` 非空；
6. 全程任何 IPC 帧中都搜不到 API Key 原文。

## 八、失败排查

| 症状 | 含义 / 处置 |
|---|---|
| 退出码 2，"未配置凭据" | 补 `AETHER_LLM_BASE_URL` / `AETHER_LLM_API_KEY`；Key 不进仓库 |
| 退出码 3，"网关 HTTP 401" | Key 错 / 过期 / 没带上 |
| 退出码 3，"404" | Base URL 少写或多写 `/v1`（最常见） |
| 退出码 3，"连接被拒 / 超时" | aetherd 没起、端口 / hostfwd 不对、防火墙 |
| 退出码 1，"回复为空" | 网关 200 但 `choices[0].message.content` 为空；核对模型名 |
| 退出码 1，"不是 JSON" | 请求打到登录页 / 门户页 → Base URL 指错；看 llm.rs 的正文片段 |
| 退出码 1，"通道非 local" | 隐私内容被路由上云，核对 `router.rs` 路由输入与 aetherd 配置 |
| 退出码 1，工具 `needs_confirmation` | L0 只读工具不该弹确认；核对被测 aetherd 版本与权限策略 |
