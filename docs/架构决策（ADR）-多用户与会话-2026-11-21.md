# ADR：多用户与会话（P3）

- 状态：**接受（账户模型先定；实现分阶段，不先写 UI 空壳）**
- 日期：2026-11-21
- 相关：`aetherd/src/accounts.rs`、`aether-ipc`（`ListUsers` / `SetPassword` / `UserInfo`）、锁屏与口令校验、IPC 权限闸门、AI 权限模型 L0–L3
- 对标：[后续发展计划（NEXT-PLAN）-2026-10-31](报告/后续发展计划（NEXT-PLAN）-2026-10-31.md) §4.3 P3、[功能缺口清单（FEATURE-GAPS）-2026-10-02](报告/功能缺口清单（FEATURE-GAPS）-2026-10-02.md) §2.3 / §9 #3 / #36、[AI权限模型（AI-PERMISSIONS）-2026-09-05](AI权限模型（AI-PERMISSIONS）-2026-09-05.md)

## 背景

### 当前事实（代码可查）

- 账户后端只有「列人类账户」与「改口令」两件事：`aetherd/src/accounts.rs` 共 162 行，公开函数为 `human_users`（第 42 行）、`list_users`（第 65 行）、`set_password`（第 76 行）；**没有增删用户、没有家目录管理、没有会话概念**。模块头注释明确：项目决定「先做单用户 + 口令；多用户留 M3」。
- IPC 侧对应 `ListUsers` 与 `SetPassword` 两个变体（`aether-ipc/src/lib.rs:155`、`:161`），`UserInfo` 结构在 `:316`；口令策略住在 `aether-ipc`，两侧共用一份。
- 口令校验：旧口令在合成器侧用 `sha512crypt` 校验（与锁屏同一套 `auth`），aetherd 只负责经 `chpasswd` stdin 写新口令；口令不进审计、不进 argv（`accounts.rs` 文件头三条安全约定）。
- 桌面状态当前是**全局单份**：设置持久化在 `/var/lib/aether/settings.json`（`aether-compositor/src/settings.rs:23`），窗口表、虚拟桌面、通知历史、已装应用（`/var/apps`）都不按用户隔离。
- 现有「注销」语义是**重启合成器**，不是切换用户（FEATURE-GAPS §2.1）；当前没有「当前是谁」作为权限判定前提。
- 权限边界现状：IPC 闸门按注册 UI 通道 + `SO_PEERCRED` 判定，非 UI 通道受限请求 403；AI 工具分 L0–L3（L0 只读 / L1 可逆写 / L2 敏感写需确认卡片 / L3 危险双重确认，见 AI-PERMISSIONS 第 9–12 行）；文件侧按路径白名单与目录权限控制，`/var/tmp` 刻意设为 0755、非 root 应用写不进（`aether-init/src/persist.rs:52-55`）。

### 边界声明

**截至本 ADR 日期，系统是单用户 + 口令模型：不支持第二个人类账户、不支持并行会话、不支持用户间文件隔离。** 账户页只列出现有人类账户并允许改口令；任何「多用户」「切换账户」「各自桌面」的入口在后端落地并验证前不得出现在界面上。

## 备选账户模型

### 模型 A：单用户 + 口令（现状延续）

| 维度 | 评估 |
|---|---|
| 权限边界 | IPC 闸门与 L0–L3 不绑定用户身份；所有已注册 UI 通道共享同一信任级别；文件 ACL 按系统目录约定，不按用户划分 |
| 桌面状态隔离 | 无隔离：设置、窗口、通知、应用全系统一份 |
| 切换方式 | 锁屏 / 重启合成器；没有用户切换 |
| 成本 | 零新增；现有锁屏、改口令、审计链路已闭环 |
| 风险 | 离开座位即他人可用；AI 权限策略无法按人区分；不满足「多人共用一台机器」的基本隐私要求 |

### 模型 B：多账户 + 会话切换（同一时刻只有一个活跃图形会话）

| 维度 | 评估 |
|---|---|
| 权限边界 | IPC 连接绑定 uid；闸门在现有通道判定上叠加「当前会话用户」；L0–L3 策略可按用户配置；审计记录操作人 uid |
| 桌面状态隔离 | 家目录独立；设置、窗口/虚拟桌面状态、通知历史、AI 时间线按 uid 分目录；已装应用区分全局应用与用户应用（第一版可先全局限定） |
| 切换方式 | 注销当前会话 → 结束合成器与用户态服务 → 以另一账户重新拉起；沿用现有「注销 = 重启合成器」语义扩展为「注销 = 结束会话」；切换期间不保留另一账户的活跃桌面 |
| 成本 | 中：账户模型与家目录、IPC 身份绑定、状态目录隔离、切换流程；不需要多实例合成器与 seat 路由 |
| 风险 | 家目录权限与路径白名单要重新核对；现有 `/var/lib/aether`、`/var/apps` 布局需要迁移方案；切换过程中的会话残留与文件句柄要清理干净 |

### 模型 C：多会话 seat（多个图形会话并行，本地 + 远程）

| 维度 | 评估 |
|---|---|
| 权限边界 | 每个 seat 独立会话身份；输入设备（键鼠/触控）按 seat 路由；服务与合成器多实例；权限策略按 seat + 用户双重判定 |
| 桌面状态隔离 | 天然隔离，但要求合成器、布局、输入、IPC 全部支持多实例 |
| 切换方式 | 会话并行存在，可在会话间切换；支持远程登录会话 |
| 成本 | 高：seat 管理、设备路由、多实例生命周期、显示输出分配（与 G4 多显示器耦合），属于平台化后期专项 |
| 风险 | 单人维护下复杂度失控；与现有单实例合成器模型冲突面大；安全面（跨会话可见性、设备劫持）需要单独审计 |

## 决策

**v0.2 之前维持模型 A（单用户 + 口令）。目标路线锁定模型 B（多账户 + 会话切换，同一时刻一个活跃会话）；模型 C（并发 seat）不在 v0.2 范围，需要时另立 ADR。先定账户模型与隔离边界，再写界面；不先做没有后端的账户管理 UI 空壳。**

### 分阶段路径

- **阶段 1 · 账户模型（不接界面）**
  - 定义账户数据模型：uid、用户名、家目录、所属组、口令状态；明确「谁有权增删账户、谁能改谁的口令」（第一版建议：仅管理员账户可增删，改他人口令需旧口令或管理员授权）；
  - 在 `accounts.rs` 现有 `list_users` / `set_password` 边界上扩展命令边界，口令仍走 stdin、不进审计；
  - 产出纯函数模型与负向用例（非法用户名、越权改口令、系统账户排除），不暴露新设置页。
- **阶段 2 · 隔离**
  - 家目录与桌面状态按 uid 拆分：`settings.json`、通知历史、AI 时间线、窗口状态落用户目录；
  - IPC 连接绑定 uid，闸门判定叠加会话身份；审计记录操作人；
  - 核对文件白名单与目录权限，确保用户间不可互读私有目录；`/var/apps` 全局/用户归属先定规则再实现。
- **阶段 3 · 会话切换**
  - 注销语义从「重启合成器」扩展为「结束当前会话并回到登录/选择账户界面」；
  - 切换流程：停用户态服务 → 清理句柄与会话状态 → 以目标账户拉起合成器与服务；
  - 补切换前后的隔离断言：A 的窗口/通知/设置不出现在 B 的会话里。
- **模型 C 前置**：seat 管理、多实例合成器、输入设备路由、输出分配；与 G4 多显示器改造联动评估。

## 理由

1. **模型 B 是当前缺口与长期目标之间的最小步长**：它解决「多人共用一台机器的隐私边界」，又不引入多实例合成器与 seat 路由这组高复杂度问题；模型 C 的价值要在有远程会话或并行桌面需求时才成立。
2. **先模型后界面**：项目既有规矩是不做没有后端的假控件（FEATURE-GAPS §6）。账户页在阶段 1/2 完成前保持现状（只读列表 + 改口令），不提前放「添加用户」按钮。
3. **复用现有安全链路**：L0–L3 闸门、确认令牌、审计日志、路径白名单已经落地；多用户改造是在其上叠加身份维度，而不是另起一套权限系统。
4. **与更新/隔离现状对齐**：现有 `/var` 持久化与单份设置布局是模型 A 的产物；阶段 2 的目录迁移必须给出 keepvar 兼容方案，不能让升级用户丢设置（参见 [镜像级OTA与A-B分区 ADR](架构决策（ADR）-镜像级OTA与A-B分区-2026-11-21.md) 的 `/var` 边界）。

## 后果

- `accounts.rs` 在阶段 1 前不增删用户命令；账户页文案维持「单用户 + 口令」现状；
- 现有锁屏、改口令、失败限流行为不回归；模型 B 落地前，「注销」仍按重启合成器理解；
- AI 权限策略编辑器（现有逐工具四态）在阶段 2 前保持全局一份，不承诺按用户配置；
- 模型 C 相关的远程登录、并发桌面需求记入路线图待评估项，不排工期。

## 什么条件下重新评估

1. 出现第二个真实使用者或多人共用一台机器的明确场景；
2. 隐私隔离成为发布门槛（如设备进入公共/教学环境）；
3. 第三方应用需要 per-user 数据边界或用户级应用安装；
4. 远程会话 / 并行桌面需求出现，触发模型 C 立项评估。
