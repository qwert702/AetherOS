## 一、装机验证（台账 #33 后半段）—— **四项判据全过**

此前 ISO 重建好了、isohybrid 也验证了，但**没有人真的装过一次机**。今天做了：

| 步 | 判据 | 实测 |
|---|---|---|
| ① 起 ISO | 系统起来、五服务 ✓ | `巡检#1 … 服务=aetherd=✓ compositor=✓ getty=✓ network=✓ ops=✓` |
| ② 安装器 | 目标盘出现分区、持久化分区建好 | `sda: sda1 sda2` + `EXT4-fs (sda2): mounted … / unmounting …` |
| ③ 从盘引导 | **拔掉光驱**也能独立引导 | `[aether-init] 持久化分区已挂载: /dev/sda2 -> /var（nodev,nosuid,errors=remount-ro）` |
| ④ 持久化 | 重启后 `/var` 的写入仍在 | 探针 `probe-1014` 重启后仍在盘上；`/var/boot.log` 记录 **第 1 次 → 第 2 次** 递增 |

证据：[装机验证（INSTALL-VERIFY）-2026-10-14.md](../docs/证据/装机验证（INSTALL-VERIFY）-2026-10-14.md)

**在哪做的、以及为什么不是构建机**（如实记）：

* 构建机内的 QEMU 是**三层嵌套**（Hyper-V → VirtualBox → QEMU）。QEMU 一起来，
  guest 的 sshd 就饿到**无法完成认证**（paramiko 与 OpenSSH 都报
  `Connection timed out during banner exchange`）；把构建机 2 vCPU 加到 4 vCPU 也没救。
* 于是改在**宿主上的 VirtualBox（headless）**做：按键注入可用、**串口落盘**（全部观测都是文本）、
  启动只要 10 秒。复现命令写进了证据文件。
* 顺带得到一条自动化经验：**注入的按键会被合成器（evdev 直读）与 tty1 的 getty 同时看到** ——
  安装命令既进了 AI 指令条、也进了 root shell。所以"AI 栏有没有收到"不能当按键送达的判据。

**没覆盖的**（别当全绿）：真机（#32）仍要物理机；安装器的交互式路径与 `--wipe` 破坏性路径本次没走。

## 二、依赖 CVE 核对（台账 #49）—— **发现 1 条真漏洞并修掉**

**"离线环境无法核对"这句只对构建机成立**：这台开发机 `crates.io` 可达、RustSec advisory-db 能拉。

| 项 | 结果 |
|---|---|
| 扫描规模 | 1310 条公告 · 154 个依赖 |
| 漏洞 | **`rustls 0.23.43` · RUSTSEC-2026-0285**（TLS 1.3 握手跨加密层级，medium 5.3） |
| 处置 | `cargo update -p rustls` → **0.23.46** + `cargo fetch --locked`（否则 `--offline` 构建会报"要发 HTTP 请求"） |
| 复验 | `cargo audit` → **0 vulnerabilities**；`cargo build/test --offline --locked` → **768 项全绿** |
| 残留 | 2 条 **unmaintained** 警告（`instant`、`ttf-parser`）**已评估并接受**；**故意不写进 ignore 名单**，让每次审计都能重新看到 |

**两条踩过的坑**：① `cargo install cargo-audit` 在本机**必然失败**（没有 MSVC Build Tools、
mingw 又缺 `libgcc_eh`，仓库靠 `rust-lld` 才能编译自己）→ 改用官方**预编译**包；
② 本机代理对 GitHub 是**抖动**的（同一条下载出现过 `schannel: handshake failed`、
也出现过"HTTP 200 但只下了 587 KB"）→ **下载后必须比大小**，别信状态码。

证据：[依赖CVE（CVE-AUDIT）-2026-10-14.md](../docs/证据/依赖CVE（CVE-AUDIT）-2026-10-14.md) + 原始 JSON。
