## 十三、找到"站点再也更新不了"的**真正根因**：`patch_values` 崩溃

### 根因（一行代码）
```python
# 错：整条正则（含环视 (?<![\d,])）也被塞进"替换串"
re.sub(pattern.replace("%OLD%", re.escape(o)), pattern.replace("%OLD%", n), text)
```
`re.sub` 的**替换串**同样会被当模板解析 → 替换串里的 `\d` 触发
`re.error: bad escape \d at position 5` → **渲染循环直接抛异常中断**。

### 为什么表现为"静默永不更新"
旧代码的顺序是**先写 `data.json` 再渲染**：
1. `data.json` 已改成新值；
2. 渲染抛异常 → 页面**一个都没写**；
3. 下次运行 `o == n` → `num()` 里 `if o and n and o != n` 不成立 → **连替换都不尝试** → 不崩溃；
4. 页面**永远停在旧值**，门禁只报"页面与数据脱节"，看不出原因。

这与用户此前修的"站点再也更新不了"是**同一个 bug** —— 之前的修复让门禁能报出来，
但**没有修到崩溃点本身**。

### 修法
```python
text = re.sub(pattern.replace("%OLD%", re.escape(o)), lambda _m: n, text)
```
替换用 **lambda**：既只放新值，又彻底不经过模板解析（新值里出现 `\` 也不会再炸）。

### 部署脚本踩的坑（值得记住）
`vmrun start` 会拉起 VMware **GUI**，GUI 子进程**继承了 stdout 管道** ——
`subprocess.run(..., capture_output=True)` 会**永远等不到 EOF** 而挂死。

**教训**：调用会拉起 GUI 的程序（vmrun/vmplayer 等）时，
要么 `stdout=subprocess.DEVNULL`，要么加超时 —— 不能无超时地捕获输出。

## 十六、安全审计与修复（同日）

对全仓库做了一轮安全审计（报告：[`docs/SECURITY-AUDIT-2026-10-02.md`](../docs/SECURITY-AUDIT-2026-10-02.md)），
并按"可用性 / 交付链路 / 文档门禁 / 底层加固"四个批次修完。**下面只列用户能感知的变化**：

### 行为变化（会影响怎么用）

- **装应用目前不可用**：v0.1.0 发布的那个 ISO 未经 `isohybrid` 处理（实测首 512 字节无 MBR
  签名），不能 dd 到磁盘引导。安装器现在会在**动目标盘之前**拒绝执行并说明原因（以前是
  先毁盘、再报错、还打印"安装完成"）。引导与 Live 桌面不受影响；重建 ISO 后装机恢复。
- **UI 密钥换了位置**：`/var/log/aether/ui.key` → **`/run/aether/ui.key`**（0600，开机重新生成）。
  它不再能被 AI 的读文件工具读到 —— 此前"任意本机进程读密钥 → 自注册 UI 通道 → 自我确认 L3"
  是一条完整链路（已实测复现）。
- **IPC 默认走 Unix socket**：`/run/aetherd.sock`（0600）。TCP 7311 仍在，但客户端只在显式
  设 `AETHER_IPC_TCP=1` 时才用它（那是给开发机 hostfwd 调试用的降级路径，因为密钥会走明文 TCP）。
- **剪贴板与读文件需要"已注册的 UI 通道"**：桌面（合成器）始终先注册，所以正常使用无变化；
  `aetherd chat` 这类没有界面的命令行用法会失去这两项能力（有意的收紧）。
- **终端粘贴更安全**：剥离控制字符，并在程序声明支持时使用括号粘贴（DECSET 2004）。
  注意：出厂 shell 是 busybox，若它不支持 2004 就会退回"换行即回车"的老行为（**待实机确认**）。
- **日志与审计权限收紧**：`/var/log/aether` 0700、审计文件 0600；审计里的剪贴板内容与
  写入内容改为脱敏记录（保留长度与指纹，仍可追溯"是不是同一份"）。
- **子进程不再继承合成器环境变量**：终端里 `env` 看不到 `AETHER_UI_KEY` 等敏感变量。

### 底层加固（用户看不见，但都是真实风险）

- `/var` 持久分区**先认身份再挂载**（ext4 卷标必须是 `AETHER`），挂载前跑 `fsck`，
  挂载选项 `nodev,nosuid`。此前候选设备表里的 `/dev/nvme0n1p2` 恰好是多数发行版的 root
  分区 —— 双系统机器上会把**别人的根分区**挂成 `/var` 并往里写日志。
- 日志与审计的写入**不跟随符号链接**（`/var/log` 指向 `/tmp` 的镜像上，预置一个
  `aetherd.log -> /etc/shadow` 就能让 root 的日志追加进任意文件）。
- PID 1 加了兜底：服务名重复、依赖成环、socket 建不出来都会**回落救援模式**而不是退出
  （PID 1 退出 = 内核 panic，只能人工救砖）。

### 门禁与文档

- `scripts/repo-stats.py --check` 从"只比对合计"扩到**三层**（合计 / 逐 crate / 逐文件），
  且三层都有**集合相等**断言 —— 删一行、改格式、新增文件不登记都会变红。
- `scripts/gen-site.py --check` 现在会**重新测量事实**（含"下载脚本内置哈希 == 已发布资产"），
  站点不再可能公布一个对不上的校验值。
- 修掉站点的三处硬伤：公布的 ISO 哈希取自**本地构建**（与 Release 资产不符）、
  ISO 文件名写成 `aetheros-v0.1.0-amd64.iso`（实际是 `aetheros-0.1-amd64.iso`）、
  "17 张界面走查图"与门禁清单的 19 张不符。
- 中英文 README 结构对齐（英文版补上「边界在哪」整节），全仓库规模/测试数字统一为实测值。
